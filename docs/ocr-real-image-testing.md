# 真实课表图片 OCR 测试

这套测试用来区分“文字识别错了”和“文字正确、但课表结构解析错了”。真实课表可能包含姓名、学号和教室信息，测试图片默认不提交到 Git。

## 1. 准备小型样本集

先收集 15–20 张经过脱敏的图片，不要只测一所学校的一种模板。至少覆盖：

- 原始高清截图、微信压缩图和手机拍屏图；
- 浅色/深色、彩色课程块、有或无明显网格线；
- 周一至周五和周一至周日；
- 单节课、连上多节、单双周、多上课地点；
- 中文、英文和数字混排的课程名与教室号。
- 另加 5 张非课表反例（聊天截图、文档、海报等），检查应用是否正确拒绝导入。

为每张图手工记录真值：课程名、星期、开始/结束节次、周次、教师、地点。

## 2. 在真机上跑完整识别链路

1. 连接 Android 手机，开启 USB 调试。
2. 在项目根目录执行：

   ```powershell
   .\gradlew.bat installDebug
   adb logcat -c
   adb logcat -s LocalOcrSchedule:I ImageScheduleImport:I *:S
   ```

3. 打开 Polaris，在课表页的操作菜单选择“导入课表图片”，再选择真实样本。
4. 在确认弹窗记录识别课程数、上课安排数、置信度和警告。未核对完不要点“确认并覆盖”。
5. Logcat 会额外输出本次识别的图片尺寸、OCR 行数、课程数、安排数和置信度，不输出课表原文。

Android Studio 也可直接运行 `app`，然后在 Logcat 中按 `LocalOcrSchedule` 过滤。

## 3. 记录可比较的结果

每张图建议记录以下指标：

- 课程格召回率 = 正确找到的上课安排 / 真实上课安排；
- 误报数 = 凭空生成的课程或上课安排数；
- 星期与节次完全正确率；
- 课程名、周次、教师、地点的分字段正确率；
- 识别失败但成功保护旧课表的次数。
- 非课表图片被误判为可导入的次数（目标为 0）。

如果 Logcat 中的 OCR 行数就明显过少或文字错误很多，问题在图像质量/OCR；如果文字大致正确，但星期、节次或课程合并错了，问题在 `ScheduleImageParser` 的结构规则。

## 4. 什么情况再引入 AI 视觉模型

先用上述样本跑出基线。如果高清截图中文字已能正确识别，但多种学校模板的结构解析仍频繁失败，再考虑增加“本地 OCR 失败后，用户明确同意才上传”的 AI 备选路径。识别成功时仍必须经用户确认才覆盖当前课表。
