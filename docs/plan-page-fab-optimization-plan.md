# 计划页悬浮新增菜单优化计划

> 状态：已完成（2026-09-04，落地版本 1.26.0 / versionCode 12600，debug APK 已交付）  
> 目标版本建议：1.26.0  
> 编写日期：2026-09-04  
> 范围：计划页、横屏平板计划管理浮层及其新增入口  
> 本文档仅定义设计和实施计划，不包含代码改动。

## 1. 背景

当前计划页在列表顶部依次放置“考试 / DDL 时间线”和“＋ 新建计划”两个整宽入口。新增计划是页面的高频主操作，但会占用首屏纵向空间；考试和 DDL 的新增还需要先进入时间线，再点击“添加事件”。手机页与横屏平板管理浮层的两个入口顺序也不一致。

本轮将新增能力统一到右下角悬浮加号中：用户点击加号后选择要添加的内容类型，直接进入对应编辑器。原“考试 / DDL 时间线”继续负责浏览和管理，不再承担新增入口。

## 2. 目标

1. 让“添加内容”成为计划页唯一、稳定、拇指可达的主操作。
2. 减少新增考试或 DDL 的操作层级。
3. 释放列表顶部空间，让用户进入页面后优先看到待办内容。
4. 保持手机、竖屏平板和横屏平板的交互语义一致。
5. 遵循现有四主题、明暗模式、Edge-to-Edge 和无障碍规范。

## 3. 非目标

- 不合并 `StudyPlan` 与 `AcademicEvent` 数据模型。
- 不修改计划提醒和课程提醒的调度规则。
- 不在本轮重构整个 `MainActivity`。
- 不修改 PDF 导入、课表展示、存储、导出或分享流程。
- 不迁移 Kotlin、Compose 或 WebView。
- 不更新历史参考文件 `preview.html`。
- 不在本轮实现计划的逾期、今天、本周等新分组。

## 4. 设计结论

### 4.1 页面空间结构

手机和竖屏平板的计划页改为页面级 `FrameLayout`：

```text
计划页容器
├── 可滚动内容
│   ├── 页面标题/摘要（后续迭代可增加）
│   ├── 考试 / DDL 时间线管理入口
│   └── 计划列表
├── 轻量内容遮罩（仅菜单展开时出现）
├── 向上展开的新增菜单
└── 主悬浮加号
```

悬浮按钮属于页面固定层，不得放入 `ScrollView`，否则会跟随列表滚动。

### 4.2 收起状态

```text
┌──────────────────────────┐
│                          │
│          计划列表         │
│                          │
│                     [＋] │
│  ┌────────────────────┐  │
│  │ 课表  计划  我的    │  │
│  └────────────────────┘  │
└──────────────────────────┘
```

- 主 FAB：56 × 56dp。
- 可见图标：24dp 矢量“＋”。
- 关闭态无障碍说明：“添加内容”。
- 仅在计划页可见；切换到“课表”或“我的”时隐藏并重置为收起态。

### 4.3 展开状态

```text
                        ┌──────────────┐
                        │ 添加考试     │
                        └──────────────┘
                        ┌──────────────┐
                        │ 添加 DDL      │
                        └──────────────┘
                        ┌──────────────┐
                        │ 新建计划      │
                        └──────────────┘
                                  [×]
```

展开项固定为三个：

1. 新建计划：打开现有计划编辑器。
2. 添加 DDL：打开学业事件编辑器，并预选“截止”。
3. 添加考试：打开学业事件编辑器，并预选“考试”。

“新建计划”离 FAB 最近，因为它是最高频操作。当前模型支持的“实践”类型暂不加入快捷菜单，仍可在考试/DDL时间线的事件编辑器中选择，避免低频入口拉长菜单。后续如数据证明实践新增频率较高，再评估第四项或“更多事件”。

菜单项使用“矢量图标＋文字”的胶囊形动作行，不使用无文字小图标：

- 每项最小高度：48dp。
- 相邻菜单项间距：8dp。
- 菜单与主 FAB 间距：12dp。
- 菜单右边缘与主 FAB 右边缘对齐。
- 标签允许随系统字号缩放，不得固定像素字号。

## 5. 定位与安全区

### 5.1 手机和竖屏平板

现有底部导航高度可配置为 56–120dp，FAB 不能使用固定的 `bottom=90dp`。底部定位应根据实时布局计算：

```text
FAB bottomMargin =
    systemBottomInset
    + NAV_FLOATING_MARGIN（18dp）
    + navVisualHeight（56–120dp）
    + FAB_NAV_GAP（12dp）
```

默认 60dp 底栏下，FAB 底边距约为 `systemBottomInset + 90dp`。

右侧定位与底部导航的可见玻璃边缘对齐：

```text
手机：systemRightInset + 10dp 页面边距 + 10dp 导航视觉内缩
竖屏平板：systemRightInset + 16dp 页面边距 + 10dp 导航视觉内缩
```

处理横屏侧边系统栏时，左右安全距应取状态栏、导航栏、手势区和挖孔区 inset 的最大值，不能只读取状态栏 inset。

### 5.2 列表底部留白

当前计划页底部留白不足以完全覆盖“底栏＋FAB”的占用高度。调整后，最后一条计划滚动到末尾时必须完整露出，并在卡片底部保留至少 12dp 空间。

底部内容留白应基于下列元素动态计算：

```text
systemBottomInset
+ 底栏外边距
+ 底栏实际高度
+ 底栏与 FAB 间距
+ FAB 高度
+ 列表末端安全间距
```

不得仅在当前 `bottomContentInset + 48dp` 的基础上假定所有设备都足够。

## 6. 交互状态

### 6.1 状态定义

- `COLLAPSED`：只显示主 FAB。
- `EXPANDED`：显示遮罩、三个菜单项和关闭态 FAB。
- `NAVIGATING`：用户已选择新增类型，菜单立即收起并打开编辑器。

### 6.2 展开

用户点击“＋”后：

1. FAB 图标由“＋”旋转为“×”。
2. 内容区出现低强度遮罩。
3. 菜单项由下向上依次淡入。
4. 无障碍焦点移动到“新建计划”。
5. TalkBack 播报“添加菜单已展开”。

### 6.3 收起

以下操作均须收起菜单：

- 再次点击主 FAB。
- 点击菜单外的内容遮罩。
- 按系统返回键或执行预测性返回手势。
- 选择任意新增类型。
- 切换底部导航页签。
- 打开考试/DDL时间线。
- 打开计划或学业事件编辑器。
- Activity 配置重建、旋转或进入后台。

收起后焦点回到主 FAB；隐藏菜单项使用 `GONE` 或等价处理，并从无障碍树中移除。

### 6.4 底部导航

遮罩只覆盖计划页内容区域，不覆盖底部导航。用户在菜单展开时仍可切换页签；切换动作同时收起菜单。

## 7. 动效

- 展开时长：160–200ms。
- 收起时长：120–160ms。
- FAB：“＋”旋转 45°成为“×”。
- 菜单项：从下方 8–12dp 位移、透明度 0→1、缩放 0.96→1。
- 菜单项可使用 25–30ms 的轻量依次出现效果。
- 遮罩透明度控制在 8%–12%，不使用重黑遮罩。
- 不使用弹跳、过冲或长路径动画。
- 系统关闭动画时立即完成状态切换，不保留延迟。

## 8. 视觉与主题

- 主 FAB 使用 `PolarisVisualTheme` 的主题强调色。
- FAB 图标颜色使用与强调色对比达标的前景色，不默认假设所有主题都适合纯白。
- 展开菜单表面使用现有页面卡片/玻璃表面 token。
- 主文字使用 `inkColor`，弱化信息使用 `mutedColor`。
- 圆角、尺寸和间距进入 `dimens.xml` 或现有 `DesignTokens`，不在新视图中增加无命名魔法数。
- 极简主题保持原有纯色表达；极光、深空、云境仅使用现有低剂量主题化玻璃规则。
- 不增加新的渐变、发光或独立阴影体系。

## 9. 空状态与文案

移除页面顶部整宽“＋ 新建计划”按钮后，空状态改为：

```text
还没有计划
点击右下角＋添加第一项
```

无障碍文案建议：

- 主 FAB 收起：“添加内容”。
- 主 FAB 展开：“收起添加菜单”。
- 菜单项：“新建计划”“添加DDL”“添加考试”。
- 展开播报：“添加菜单已展开，共3项”。

所有新文案写入 `strings.xml`，不在 Java 中硬编码。

## 10. 平板适配

### 10.1 竖屏平板

- 行为与手机一致。
- FAB 与居中内容列的右边缘对齐，不贴超宽屏物理右边缘。
- 列宽变化或分屏时重新计算位置。

### 10.2 横屏平板

横屏平板没有独立计划 tab，用户从课表右侧“本周计划”面板进入计划管理浮层：

- 不在全屏根节点右下角显示计划 FAB。
- 在右侧计划管理浮层内部创建独立 FAB。
- FAB 按浮层右边缘和系统底部 inset 定位。
- 菜单展开时遮罩只作用于管理浮层内容，不遮住整个课表。
- 常驻“本周计划”小面板继续保留“管理”入口，不在狭窄小面板内叠加 FAB。

手机页和横屏管理浮层应复用同一套菜单项定义与动作路由，但各自持有独立视图引用，避免当前单个 `planAddButton` / `planListContainer` 被后构建页面覆盖的问题扩大到 FAB 状态。

## 11. 无障碍要求

- 所有触控目标不小于 48 × 48dp。
- 可操作项之间至少保留 8dp 间距。
- 图标必须具有明确 `contentDescription`。
- 展开状态不能只依靠旋转或颜色表达。
- TalkBack 顺序：主 FAB → 新建计划 → 添加DDL → 添加考试；收起状态只聚焦主 FAB。
- 支持系统返回键、预测性返回、键盘 Enter/Space 和方向键导航。
- fontScale 1.3 与 2.0 下，菜单文字不截断；必要时胶囊宽度自适应而不是降低字号。
- 四主题×明暗模式下检查正文和图标对比度。

## 14. 验收标准

### 功能

- 计划页不再显示整宽“新建计划”按钮。
- 点击 FAB 可展开“新建计划 / 添加DDL / 添加考试”。
- 三个入口均直接打开正确编辑器和预选类型。
- 返回、点空白、切页、打开编辑器后菜单都会收起。
- 考试/DDL时间线仍可正常查看、编辑和删除事件。
- 计划与学业事件的存储、完成状态和提醒行为不变。

### 布局

- FAB 不随列表滚动。
- FAB 不与底部导航、系统手势区、挖孔或侧边导航栏重叠。
- 用户调整底部导航高度后，FAB仍保持正确间距。
- 最后一条计划可完整滚动到 FAB 上方。
- 竖屏平板 FAB 与内容列右缘对齐。
- 横屏平板 FAB 只出现在计划管理浮层内部。

### 视觉与交互

- 主 FAB 是页面最明显的新增入口，但不压过计划内容。
- 展开菜单文字清晰，不要求用户猜图标含义。
- 动画关闭时交互仍完整可用。
- 四主题和明暗模式下均无硬编码错色。
- 所有操作目标达到 48dp，TalkBack状态和焦点顺序正确。

### 回归

- PDF导入与周课表展示不受影响。
- 三个底部导航页签切换正常。
- 横屏平板本周计划侧栏及“管理”入口正常。
- 旋转和Activity重建后不会残留展开菜单或遮罩。
- `lintDebug` 维持0 error。

## 15. 风险与控制

| 风险 | 影响 | 控制措施 |
|---|---|---|
| FAB按固定值定位 | 自定义底栏高度时重叠 | 统一读取 `navVisualHeight` 和完整 WindowInsets |
| FAB放入滚动容器 | 按钮随列表滚走 | 使用页面级或管理浮层级固定 overlay |
| 列表底部留白不足 | 最后一项被FAB遮挡 | 按底栏、间距、FAB高度动态计算 reserve |
| 手机和管理浮层共用单一视图引用 | 主题刷新或状态更新命中错误页面 | 两种容器分别持有实例，只共享配置和回调 |
| 展开菜单未处理Back/切页 | 留下遮罩或错误状态 | 建立单一收起入口，并接入所有生命周期节点 |
| 直接新增考试/DDL改变旧流程 | 类型默认值或编辑状态错误 | 保留旧入口，新增显式预选类型重载并写回归测试 |
| 横屏侧边系统栏inset遗漏 | FAB靠边或被系统栏遮挡 | 左右安全距取bars/nav/gestures/cutout最大值 |
| 主题强调色与白字对比不足 | 部分主题可读性下降 | 根据实际填充色选择前景色，不写死白色 |
| 展开项过多 | 小屏和横屏拥挤 | 首版限定3项，实践保留在完整事件编辑器 |

## 17. 完成定义

只有在以下条件全部满足后，本轮才算完成：

1. 三种新增入口均可直达正确编辑器。
2. 手机、竖屏平板和横屏平板的定位规则全部通过。
3. 无遮挡、无状态残留、无无障碍焦点泄漏。
4. 四主题×明暗、fontScale和系统导航矩阵通过。
5. 单元测试、仪器测试、Lint和Debug构建通过。
6. 构建APK交付时已同步更新语义化版本号。
