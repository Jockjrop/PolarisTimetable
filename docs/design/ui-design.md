# Polaris课程表 UI 设计

## 1. 视觉基调

UI 基于 `preview.html` 的 Polaris 视觉风格迁移到 Android 原生 View：

- 背景：清爽浅蓝，允许轻微渐变或分层蓝色背景。
- 文字：深蓝黑 `#172033` 作为主文字，灰蓝 `#667085` 作为辅助文字。
- 卡片：白色半透明感可用浅色圆角背景近似实现。
- 课程块：高饱和但柔和的蓝、青、珊瑚、紫、黄、粉。
- 课表：横向滚动周视图，时间列固定在视觉左侧，课程块卡片式排列。
- 导航：底部保留“课表 / 学习 / 我的”。

不使用 WebView 加载 `preview.html`。所有界面均使用 Android Java 原生 View、Drawable 和自定义 View 逐步实现。

## 2. 全局布局

### 手机端

- 竖屏优先。
- 顶部是今日概览和周次信息。
- 中间是横向可滚动周课表。
- 底部是固定三栏导航。
- 课程详情使用底部弹窗或居中弹窗。

### 平板端

- 利用更宽列宽展示完整周课表。
- 顶部概览和周课表可以左右或上下组合，但第一阶段继续沿用上下结构。
- 横屏时尽量减少横向滚动。
- 课程详情弹窗可使用居中宽卡片。

## 3. 页面设计

### 3.1 首页 / 今日概览

页面目标：

- 让用户打开 App 后立刻知道今天有没有课、下一节课是什么、本周处于第几周。

主要组件：

- 顶部状态区：`Polaris Week 18`、今天课程数量、日期。
- 快捷按钮：导入 PDF、导出、分享、更多。
- 统计卡片：本周课程数、实验/实践数、当前周次。
- 日期条：周一到周六或周日，今天高亮。
- 今日课程列表：按时间排序展示今日课程。
- 底部导航。

用户操作流程：

1. 查看今天课程数量。
2. 点击日期切换某天概览。
3. 点击课程打开详情。
4. 点击导入 PDF 进入导入流程。

手机端布局：

- 顶部标题占满宽度，按钮在右侧 2x2 小网格或单行图标。
- 统计卡片三列。
- 今日课程列表纵向排列。

平板端布局：

- 顶部标题、统计卡片和操作按钮在一行内更舒展。
- 今日课程列表可与迷你周课表并排。

状态处理：

- loading：顶部副标题显示“正在解析课表...”，今日列表显示骨架占位。
- empty：显示示例课表和“导入 PDF”按钮。
- error：显示失败原因和重新导入按钮。
- success：显示真实课程和更新时间。

### 3.2 周课表页

页面目标：

- 展示当前周完整课程安排，支持横向滚动和周次切换。

主要组件：

- 周次切换：上一周、本周、下一周。
- 日期列头：周一到周六，后续支持周日。
- 时间列：1-11 节和上课时间。
- 课程块：课程名、地点、周次提示。
- 当前日期高亮。
- 空周提示。

用户操作流程：

1. 进入课表页看到本周课程。
2. 左右滚动查看星期。
3. 上下滚动查看节次。
4. 点击课程块打开详情。
5. 切换上一周/下一周。

手机端布局：

- `HorizontalScrollView + ScrollView + FrameLayout` 可继续使用。
- 每天列宽约 70dp，时间列约 50dp。
- 课程块最少显示课程名和地点，长文本截断。

平板端布局：

- 每天列宽约 120-150dp。
- 时间列约 64dp。
- 课程块可显示教师和周次。

状态处理：

- loading：课表区域覆盖半透明 loading。
- empty：显示“本周没有课程”而不是全局无数据。
- error：保留上一次课表，顶部提示解析失败。
- success：课程按当前周次过滤显示。

### 3.3 PDF 导入页

页面目标：

- 帮用户选择 PDF，并明确支持范围和解析进度。

主要组件：

- 文件选择按钮。
- 最近导入记录。
- 支持说明：文字型教务系统 PDF。
- 解析进度：读取文件、提取文字、识别表格、生成课程。
- 失败提示入口。

用户操作流程：

1. 点击“选择 PDF 课表”。
2. 系统文件选择器返回 URI。
3. 页面进入解析中。
4. 成功后进入解析结果确认页。
5. 失败后展示原因和重试。

手机端布局：

- 单列布局。
- 主按钮明显。
- 说明文字简短。

平板端布局：

- 左侧导入操作，右侧展示示例说明或最近记录。

状态处理：

- loading：显示分步进度。
- empty：显示导入引导。
- error：显示错误类型、重试和查看日志。
- success：显示识别数量并跳转确认页。

### 3.4 课程详情弹窗

页面目标：

- 让用户快速确认课程完整信息，并为后续编辑打基础。

主要组件：

- 课程名。
- 时间：星期、节次、具体时间。
- 周次：范围、单双周、项目周。
- 地点：校区、教室。
- 教师。
- 类型：讲课、实验、实践、网络。
- 解析来源：原始 PDF 文本。
- 操作按钮：关闭、编辑、添加提醒。

用户操作流程：

1. 点击课程块。
2. 弹出详情。
3. 查看详情或复制地点。
4. 关闭或进入编辑。

手机端布局：

- 底部弹窗，占屏幕 45%-75%。
- 内容纵向滚动。

平板端布局：

- 居中弹窗，最大宽度 520dp。

状态处理：

- loading：一般不需要。
- empty：字段为空时显示“未识别”。
- error：低置信度字段显示提示。
- success：完整展示。

### 3.5 解析结果确认页

页面目标：

- 在导入后让用户确认识别结果，避免错误课表直接覆盖。

主要组件：

- 解析摘要：识别课程数、低置信度项、错误数。
- 课程列表：按星期和节次分组。
- 低置信度标记。
- 原始文本查看入口。
- 操作按钮：确认保存、重新导入、稍后编辑。

用户操作流程：

1. 解析成功后进入确认页。
2. 用户浏览课程列表。
3. 点击可疑课程查看原始文本。
4. 确认保存进入周课表。

手机端布局：

- 摘要固定在顶部，列表滚动。

平板端布局：

- 左侧列表，右侧显示选中课程详情和原始文本。

状态处理：

- loading：生成确认数据时显示进度。
- empty：提示未识别到课程。
- error：展示解析错误列表。
- success：展示可确认结果。

### 3.6 设置页

页面目标：

- 管理课表显示、学期、颜色、导入和导出偏好。

主要组件：

- 当前学期。
- 当前周次。
- 显示周末开关。
- 颜色策略：按星期、按课程、手动。
- 导出设置。
- 解析日志开关。
- 关于应用。

用户操作流程：

1. 进入“我的”。
2. 修改周次或显示设置。
3. 返回课表后立即生效。

手机端布局：

- 设置项单列分组。

平板端布局：

- 左侧分组导航，右侧设置详情。

状态处理：

- loading：读取本地设置。
- empty：使用默认设置。
- error：设置保存失败 Toast。
- success：变更后轻提示。

### 3.7 导出 / 分享页

页面目标：

- 生成适合保存和分享的课表图片或 PDF。

主要组件：

- 导出范围：本周、指定周、整学期。
- 导出格式：图片、PDF。
- 预览区域。
- 分享按钮。
- 保存按钮。

用户操作流程：

1. 选择导出范围。
2. 选择格式。
3. 生成预览。
4. 保存或分享。

手机端布局：

- 参数选择在顶部，预览在下方。

平板端布局：

- 左侧参数，右侧大预览。

状态处理：

- loading：显示“正在生成...”。
- empty：没有课程时导出示例或提示先导入。
- error：生成失败，保留重试。
- success：显示预览和分享入口。

### 3.8 错误状态页

页面目标：

- 清楚说明无法继续的原因，并给出下一步。

主要组件：

- 错误标题。
- 具体原因。
- 建议操作。
- 重新导入按钮。
- 查看诊断日志。

常见错误：

- PDF 打不开。
- PDF 没有可提取文字。
- 未识别到星期列。
- 未识别到节次。
- 权限失效。

手机端布局：

- 居中信息加底部主按钮。

平板端布局：

- 居中窄面板。

状态处理：

- error 为主。
- 若有部分课程，提供“查看已识别课程”。

### 3.9 空状态页

页面目标：

- 没有真实课表时仍展示产品能力，并引导导入。

主要组件：

- 示例今日概览。
- 示例周课表。
- “导入 PDF”主按钮。
- 简短说明“当前为示例课程”。

手机端布局：

- 示例课表可直接复用当前 `displayCourses()`。

平板端布局：

- 示例课表完整铺开。

状态处理：

- empty：展示示例。
- loading：导入后切换为解析中。
- success：替换为真实数据。
- error：回到空状态并显示错误提示。

## 4. 课程颜色策略

第一阶段沿用当前按星期分配：

- 周一：蓝
- 周二：珊瑚
- 周三：青
- 周四：紫
- 周五：黄
- 周六：粉

后续支持按课程名稳定分配颜色：

- 以课程名 hash 到调色板。
- 同一课程多个上课时间使用同一颜色。
- 用户手动修改颜色后保存到本地设置。

## 5. 原生实现建议

- 短期：继续用 Java 动态 View，先提取 `ScheduleBoardViewBuilder` 或 `ScheduleBoardView`。
- 中期：将课程块、时间列、日期条拆成独立 UI 类。
- 长期可选：如未来迁移 Kotlin/Compose，需单独评估，不在当前阶段执行。
